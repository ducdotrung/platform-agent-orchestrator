Architecture review · public Sock Shop sample

From AI demos to a governed control plane.

The new repository turns the earlier engineering-context platform into durable LangGraph workflows with authenticated admission, human approval, idempotent effects, PostgreSQL recovery, and optional Langfuse evaluation.

Core thesis

Context is necessary. Control is what makes it operable.

The old presentation showed how service graphs, code knowledge, wiki surfaces, and alert intelligence create useful engineering context. This version adds the execution contract: who may start work, what state is authoritative, how a run resumes, and how side effects remain safe under replay.

One admitted alert

The request returns before durable workflow execution begins.

The API transaction establishes identity and work. A separate worker owns execution, making restart and backpressure explicit.

Authenticate

HMAC signature binds key ID, timestamp, nonce, method, path, workflow, scope, and body digest.

Admit atomically

Persist event, run, initial delivery job, and audit record with stable idempotency semantics.

Claim with fence

Worker leases one due job using a unique lease token and records an attempt.

Invoke graph

Load the bounded event, use run ID as LangGraph thread ID, and execute the alert graph.

Fence effects

Reserve notification identity before provider execution; store receipt or ambiguous state.

Commit outcome

07
Authoritative state model

Four planes answer four different questions.

Keeping these stores separate prevents recovery logic from depending on sampled traces or provider-specific checkpoint tables.

Business state

What was accepted, decided, approved, delivered, and retained?

  • Events, runs, delivery jobs and attempts.
  • Approvals, feedback, side effects.
  • Replay claims and append-only audit.

Graph state

Where is this execution and what bounded node state can resume?

  • LangGraph checkpoint and pending writes.
  • Stable thread ID mapped to run ID.
  • Saver-owned schema and migrations.

Knowledge state

What external evidence was believed at a revision, and why?

  • Owned by service-graph-toolkit.
  • Only bounded evidence references cross in.
  • No complete source corpus in workflow state.

Telemetry

How did execution behave, and how should a release be evaluated?

  • Prometheus and safe structured logs.
  • Optional Langfuse traces and scores.
  • Never workflow authority or audit proof.
08
At-least-once delivery

Duplicates are expected. Logical effects are still singular.

PostgreSQL is the broker for the public sample. Leases bound worker ownership; idempotency and receipt records bound external effects.

Delivery state machine

Lease every attempt

pending→ leased→ completed
leased→ retry_wait→ leased
leased→ failed_terminal

An expired lease closes the prior attempt as worker_lost; a new worker receives a new token and attempt number.

Side-effect protocol

Reserve → call → receipt

  1. Derive stable key from logical operation.
  2. Persist request hash and exclusive claim.
  3. Call provider only while claim is valid.
  4. Persist accepted receipt on success.
  5. Persist unknown after ambiguous timeout; reconcile before retry.

The sample provider only records a local receipt. External Teams/Jira delivery is intentionally disabled.

Checkpoint replay may execute a node again. The effect record—not hope—prevents a second logical notification.
09
Human control

An approval is bound to one exact interrupted action.

LangGraph interrupt() pauses execution; the application database records the reviewer decision and queues a separate resume job.

Interrupt

Persist the proposal

  • Approval version and run version.
  • Action hash and bounded kind.
  • Expiry and interruption timestamp.
  • No reviewer identity yet.
Decision

Authenticate the human

  • Reviewer ID and same team scope.
  • Reason and approved/rejected decision.
  • Exact action hash, versions, expiry.
  • Idempotency claim before approval row.
Resume

Queue, do not inline

  • Create a durable resume delivery job.
  • Worker loads the fenced decision.
  • Resume the same checkpoint thread.
  • Reject stale, altered, repeated decisions.

Local runtime topology

One image, explicit roles, migrations before readiness.

Compose is the selected Gate G2 target. It isolates the public sample and gives CI one reproducible recovery path.

Initialization

One-shot roles

  • db-bootstrap creates saver database.
  • app-migrate owns Alembic schema.
  • checkpoint-migrate calls saver setup.
  • API/worker never run DDL at startup.
Long-lived

API + worker

  • API exposes loopback port 8080.
  • Worker has no webhook secret.
  • Separate role-specific readiness.
  • Graceful SIGTERM and recoverable leases.
Hardening

Small blast radius

  • UID/GID 10001, read-only root filesystem.
  • All capabilities dropped.
  • No-new-privileges and bounded resources.
  • Internal database network; external egress off.

Honest architecture gap analysis

What the code does today is not yet the whole ADR target.

These gaps are the engineering agenda—not footnotes to hide during a review.

Runtime gap

Sync graph inside async worker

The worker loop and repository are async, but the registry invokes synchronous graphs in a worker thread. C-track I/O ports should complete the async boundary rather than grow unbounded thread offloading.

Adapter gap

Demo mode only

Bootstrap rejects any non-demo adapter mode. The live read-only service graph adapter, structured model gateway, and external notification contract are not connected.

Evaluation gap

Inputs exist; runner does not

The fixed 24-case dataset, rubric, provenance checks, and protected-locator convention are implemented. Comparable replay reports and threshold gates remain D02/D03.

Operational gap

Manifest exists; gate evidence is incomplete

Real PostgreSQL and process recovery passed, but image build, Compose topology, dashboard/runbook exercises, restore, and rollback still need execution evidence.

No external notification, company identity provider, production traffic, protected dataset, or mutation capability is authorized by the current sample.

Dependency-ordered roadmap

Close the local gate, then replace one adapter at a time.

The sequence preserves failure isolation and keeps every cross-repository contract reviewable.

1 · unblock

Close G2

  • Push current commits or use a Docker-capable host.
  • Run image build and Compose config.
  • Smoke a new run before/after worker SIGTERM.
  • Capture gate evidence; do not infer it.
2 · C01–C04

Contract adapters

  • Future sre-alert-agent ingress contract fixture.
  • Read-only Sock Shop graph MCP adapter.
  • Structured semantic reasoning gateway.
  • Notification contract behind effect protocol.
3 · C05–D05

Integrate + evaluate

  • Validated bootstrap adapter selection.
  • Provisional/review fallback for weak evidence.
  • Deterministic replay reports and CI thresholds.
  • Immutable release metadata.
4 · E track

Operate + learn

  • SLOs, dashboards, alerts, and runbooks.
  • Shadow mode with zero visible effects.
  • Promotion/rollback and bounded pilot config.
  • Review measured results at each gate.
Add the model only where semantic judgment is required. Keep parsing, routing, authorization, evidence validation, and delivery policy deterministic.

Talk track
  1. Submit the same signed event twice; show one stable run.
  2. Inspect run/job/attempt state separately from checkpoint state.
  3. Show an interrupted graph and approval action hash/version.
  4. Resume with the same run/thread ID.
  5. Replay notification execution; show one durable logical receipt.

Questions for the tech team

The next decisions are contract and operations decisions.

The orchestration foundation is less risky than prematurely choosing the wrong adapter packaging, identity, or telemetry boundary.

Runtime

Async migration

Do we complete native async ports/graphs during C02–C05, or explicitly retain a bounded sync compatibility boundary for the public adapter?

Provider packaging

Graph MCP artifact

Should service-graph-toolkit publish a pinned image/package, or is host-mode stdio with an operator-supplied read-only checkout acceptable for G3?

Observability

Langfuse data policy

Where is Langfuse hosted, which metadata class is allowed, what is sampled, and who owns retention/deletion before enabling it beyond no-op?

Identity

Company reuse

Which real workload and human identity mechanisms replace sample signatures before any company integration?

Delivery

Ambiguous outcomes

Can the eventual alert provider look up an idempotency key and reconcile uncertain sends, or must that adapter remain disabled?

Gate ownership

Who closes G2/G3?

Name the operator who owns container evidence, replay review, rollback exercise, and the explicit go/no-go record.
